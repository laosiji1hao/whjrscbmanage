# 债券业务管理系统 · 业务表单字段联动规则（SPEC）

> 适用页面：`business_form`（新增 / 编辑 / 创建分期）、`business_look`（查看 / 变更申请，updaterType=0/1）。
> 简称约定：**form**＝`business_form` 三个模式；**look**＝`business_look` 两个变体；「两个表单」= form + look。
> 校验时间：2026-10-13。前端实现：`pages_src/*.part.js` + `tools/prelude.part.js`。

## 一、通用联动（两个表单都有）

| # | 触发字段 | 联动动作 |
|---|---|---|
| 1 | **客户编号**（失焦） | 调云接口 **226010** 查 ECIF：查到 → 回填 **ECIF客户号** 与 **融资人名称**；页面已有值且与查询结果不一致 → `Modal.confirm`「是否以此为准」，确定才覆盖；查不到 → 提示「该客户编号查询的ECIF客户号/客户名称不存在」，ECIF 留空手填 |
| 2 | **ECIF客户号**（失焦） | 手工输入前补零到 **17 位**（如填 `123` → `00000000000000123`）；226010 回填值保持原样 |
| 3 | **内部评级** int_rating | → **客户分类** customer_type（form 只读、look 可改）：`AAA+ / AAA / AAA-` → 一类 `0`；`AA+ / AA / AA- / A+ / A / A- / BBB+` → 二类 `1` |
| 4 | **币种 / 初始金额** | → **折人民币**：人民币 ×1、美元 ×6.8（固定汇率）。**form 双写** `rmb_amount` 与 `balance`；**look 只折算 `rmb_amount`**（不写 balance，与原 cpt 口径一致） |
| 5 | 资金发放开关 `fund_account_flag` | 是 → 显示资金发放/募集账号框，账号失焦调 **226014** 校验（`status != "AS00"` 提示并清空）；否 → 清空并隐藏 |
| 6 | 资金监管开关 `supervise_account_flag` | 同上（是 → 显示资金监管/回款专户框 + 226014 校验；否 → 清空隐藏） |
| 7 | 金融批复开关 `js_remark_flag` | 是 → 显示金融市场部批复管理要求框；否 → 清空并隐藏 |
| 8 | 行权开关 `exercise_flag` | 是 → 显示 **行权日期=到期日**；否 → 清空并隐藏行权日期 |
| 9 | 分期开关 `installment_flag` | **是 → 显示【还款计划 / 还款计划明细】区；否 → 整区隐藏 + 清空明细与隐藏 JSON** |
| 10 | **添加还款计划**按钮（仅分期=是时显示） | 点击先校验分期=是（否则拦截提示）；打开**还款计划弹窗**（携带当前债券编号 + 已填计划 initial 回显）；弹窗「提交」回写明细人读串 + 隐藏 JSON，点「关闭」关弹窗 |

## 三、business_look 独有联动

| 触发字段 | 联动动作 |
|---|---|
| **是否有通道费** `is_passage` | 否(0) → 清空并隐藏通道费金额，**上存利率 = 票面利率 − 增值税 − 附加税**（读配置表 `bus_upper_storage_config`）；是(1) → 显示通道费金额，计算公式见下 |
| **通道费金额 / 投资利率** | =是 时联动重算上存利率：**上存利率 = 投资利率 − 增值税 − 附加税 − 通道费金额**（`parseFloat(toFixed(6))`） |
| 监管开关 `supervise_account_flag` | **反向联动「是否涉及我行资金监管」`fund_used_flag`**：是 → fund_used_flag=是；否 → fund_used_flag=否（form 无此字段） |
| 债券编号 `bond_code` | **可编辑**；可重复。还款计划并入主表 `installment_plan`、审批流按 `biz_uuid` 关联，**改号无需迁移任何关联表** |
| 加载初始化 | 上存利率等配置**等 config 就绪再算**（避免加载竞态算出 0） |

## 六、业务生命周期（状态流转）

当前状态定义（`bus_bond_business.status`）：

| 编码 | 名称 | 含义 | 可进入 | 主要操作 |
|---|---|---|---|---|
| 0 | 未完善 | 草稿（填了未提交） | 新增未提交 / 外部预置 | 完善 → 提交(226006) → 1 |
| 1 | 审核中 | 已提交，审批流进行中 | 提交新增 / **被否决后重新提交** | 只读，不可编辑 |
| 2 | 新增审核失败(新增被否决) | **仅「新增申报」被否决**（变更/换经理/中止被否不会落到此状态，业务保持原状） | 新增审批否决（由 1 转入） | **编辑 → 重新提交 → 1（再次发起新增）** |
| 3 | 生效中 | 审批通过、业务存续 | 审批通过（由 1 转入） | 变更申请(226007) / 换经理 / 创建分期 / 中止 |
| 4 | 已过期 | 到期 | 到期（由 3 转入） | 中止 |
| 5 | 已中止 | 业务终止 | 中止（由 3/4 转入） | 只读 |
| 6 | 已退休(PASS_RETIRE) | 被新批准记录取代而退休的旧记录/草稿（后端六态机 `Constant.BizStatus.PASS_RETIRE`） | 新记录审批通过落库时由后台将同 bond_code 的旧记录置 6 | 终态，**所有视图无条件排除**（列表/导出均 `status != 5 AND status != 6`） |

**流转示意**（终态 5 中止、6 退休均不向用户展示）

```
新增(填表,0) ──提交226006──▶ 1审核中 ──通过──▶ 3生效中 ──到期──▶ 4已过期 ──中止──▶ 5已中止
                              │否决               │变更申请/换经理/创建分期
                              ▼                   │
                          2新增审核失败 ──编辑──▶ 重新提交(226006) ──▶ 1审核中
```

- **被否决(2)的再次发起路径**（本轮新增）：申报列表与业务池都纳入 status=2；点「编辑」打开申报表单（business_form edit），修改后保存即重新发起新增（226006 更新分支，状态回 1、产生新审批流）。
- **生效中(3)的变更路径**：点「编辑」打开查看/变更（business_look → 226007）。
- **审核中/已中止**：只读，不提供编辑入口。

- **状态 6 的出处**：SQL 注释只有 0~5，但后端 `Constant.BizStatus` 明确是**六态机**（`PASS_RETIRE=6`），且三个列表/导出查询均 `status != '5' AND status != '6'` 排除。6 = 同编号新记录审批通过时，旧审核中记录/草稿被后台置为「已退休」。

### 身份与唯一性（补充：2026-10-13）
- **业务唯一身份 = `biz_uuid`**（`uk_biz_uuid` 唯一）；`bond_code` 已**拆除 `uk_bond_code` 唯一约束**、降级为可重复的普通债券编号。
- **其余表一律按 biz_uuid 关联**：`iassist_flow_data.business_no` 存 biz_uuid（审批流主链路）、`bus_manager_change_history.business_id` 存 biz_uuid；还款计划已并入主表，`bus_repayment_schedule` 已删除（代码不再引用）。同号多笔业务不再交叉锁定。
- 由此支撑：**「创建分期」沿用同一债券编号生成新业务**（新 biz_uuid 即新记录），后端 saveBusiness 不再按 bond_code 查重拦截。
- **新增被否决(2) 保留 bond_code**，重报时表单自动预填旧编号（自动沿用、无需重填）。

### 还款计划并入主表（2026-10-13）
- **还款计划只存 `bus_bond_business.installment_plan`（JSON 数组）**，独立表 `bus_repayment_schedule` 已删除（代码不再引用）。
- 明细文本人读串与计划弹窗均从该 JSON 解析；业务间互不干扰（不再按 bond_code 关联，**同号业务不会串计划**）。
- 新增/重报/变更保存一律整体回写 `installment_plan` JSON；计划弹窗只读父页 initial（无独立表查询）。
